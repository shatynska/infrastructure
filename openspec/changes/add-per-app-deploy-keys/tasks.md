- [x] 1.5 Replace the current whole-file `authorized_keys` `copy` task with one driven by `deploy_apps`: for each entry, an `authorized_keys` line for that application's public key carrying `restrict,command="/usr/local/bin/deploy-receive <name>"` — the `restrict` option (OpenSSH ≥ 7.2) additionally disables port/agent/X11 forwarding and pty allocation for that key, so a leaked key can't be used to tunnel through the host even though `command=` alone already prevents it running anything but the one forced invocation. This likely needs the `ansible.posix.authorized_key` module (supports `key_options`); pin it in `ansible/requirements.yml` if newly introduced. ## 5. Rollout

**Ordering matters here.** The platform key's `authorized_keys` entry and `platform-deploy.yml`'s deploy steps must change together, not independently, or a `platform/**` merge landing in between uses a workflow that doesn't match the host's current state (old workflow against a newly-restricted key, or new workflow against an unmodified key — either fails or behaves unpredictably; see design.md's Migration Plan). Treat 4.3 through 5.2 below as one coordinated maintenance window: no merge touching `platform/**` should land between starting 4.3 and completing 5.2.

- [x] 5.1 With 4.3 already merged (so any subsequent `platform/**` trigger uses the new tar-pipe workflow), run the updated playbook against `prod` (`ansible-playbook ... --limit prod`) — this provisions `deploy-receive`/`app-deploy`, restricts the platform key to `restrict,command="/usr/local/bin/deploy-receive platform"`, and provisions `commerce-ops`'s entry. `platform-compose-deploy` and its old sudoers entry are left in place, unreachable but present, until 5.6. Confirm idempotency (a second run reports no changes).
- [x] 5.2 Immediately after 5.1, validate end-to-end: trigger a real or dummy `platform/**` change and confirm the deploy succeeds via the new tar-pipe path. This closes the maintenance window opened at 4.3 — once this passes, ordinary `platform/**` merges are safe again.
