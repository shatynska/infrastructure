## 2. The render step escapes what it writes

- [x] 2.1 In `.github/workflows/platform-deploy.yml`'s *Render .env from secrets* step, add the escaping point: a function taking a name and a value, applying `\`→`\\`, then `"`→`\"`, then `$`→`$$`, and writing `NAME="<escaped>"` itself. Use bash parameter expansion into a variable — **no `$(…)` anywhere in the step**, since command substitution strips trailing newlines and a GitHub secret may end in one, so capturing would introduce a corruption at the moment the rest of them were being removed. **The escaped variable is written to the file and goes nowhere else**: it is a transformed copy of a secret, and GitHub's masking is registered against the untransformed one, so a step that echoes it for debugging puts a credential in a log in the clear. This change is what creates that form, so the prohibition belongs with it
- [x] 2.2 Replace the eight `printf` lines with eight calls to it. The block should contain the calls and nothing else, which is the property task 1.3's check reads
- [x] 2.3 Add the report Decision 9 specifies: after rendering, name each variable whose value contains a `$`, a `"`, an apostrophe, a `#`, a **line break**, or a backslash, or which carries leading or trailing whitespace, as a GitHub Actions notice. Take the set from Decision 9's table rather than re-deriving it — six members have a measured corrupting position and the backslash is a stated margin. **Detect by presence anywhere in the value, never by position**, even though `"`, `'` and `#` corrupt only in particular ones: positional detection re-derives this parser's rules in workflow code nothing here can exercise, and round 6 measured those rules doing something nobody would guess — a space before a `#` begins a comment and a tab before it does not. **The name only** — no value, no character, no count of characters. Where none qualifies, say that explicitly rather than emitting nothing, since an absent notice and a notice reporting nothing are the same output to a reader and only one of them is evidence
- [x] 2.4 Rewrite the comment block above the step. It currently ends by telling the reader the `$` case is open, that `docs/backlog.md` `render-the-env-file-so-a-secret-survives-it` is the remaining half, and that the values are generated with `openssl rand` **because** of that gap. All three sentences go stale here. Keep the three shell-layer measurements it records — they are what justifies the `env:` block and are still true — and say what replaced the gap: the escaping rule, that it was measured rather than reasoned, where the harness is, and that the obligation stops at the parser rather than at the service process

The shell layer is closed and this change does not touch it; the two fixes are independent, and stacking them in one step's history is how a later reader concludes one of them was the fix. It is also what `assert-no-secret-is-built-into-a-url` will read

## 3. The harness is committed

- [x] 3.1 Commit the measurement harness as `tools/env-rendering-probe/` **at the repository root** — the one-service Compose project and the driver scripts that produced every table in `design.md`, including the `env_file:` variant of round 4 and the current-rendering sweeps of rounds 5 and 6. Its README states what it is for, how to run it, and what it is **not**: not a test, in none of `AGENTS.md`'s three rows, run by no pipeline.

  **Not under `platform/`**, which is where the first draft put it: `platform-deploy.yml` triggers on `push` to `main` with `paths: ["platform/**"]`, so every future edit to a probe value or its README would merge as a production deploy of the shared stack to every opted-in stack and wake the reviewed Environment's approval gate for a change no host receives. And not in the change's own directory, which moves when the change is archived — the harness has to outlive it and hold a stable path, since `design.md` Decision 6's deferred round-trip check starts from it
- [x] 3.2 Check it does not disturb what already reads this tree. **The open question is Dependabot**: `.github/dependabot.yml` records that the Compose fetcher does not descend into subdirectories, so the configured `/platform` entry will not reach a probe's compose file wherever it sits — and the requirement is that every file declaring a service image is covered or **reported** as uncovered. Establish which of those this is and act accordingly rather than assuming a root-level `tools/` directory is invisible to it.

  Two that were expected to be problems and are not, recorded as checked rather than left open. And the image-pin assertions anchor on the exact path `platform/docker-compose.yml`, so they neither fail on a probe's compose file nor watch its pin — the second half being a small argument for pinning it in the probe's own README instead
