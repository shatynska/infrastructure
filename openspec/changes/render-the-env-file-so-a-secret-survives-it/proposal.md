## Why

`platform-deploy.yml` writes each of eight values into `platform/.env` as `printf 'NAME=%s\n' "$VALUE"`, and Compose's dotenv parser then reads that file. That parser processes the value: it expands `$`, strips quotes, and drops trailing whitespace. So a secret an operator entered into a GitHub Environment is not necessarily the secret the service receives, and the difference is silent — the container starts, reports healthy, and fails only at whatever needed the credential. postgres-exporter spent an unknown period in exactly that state, which is what `alert-on-the-exporter-being-unable-to-read-postgres` records.

This is the second of the two layers that entry pair names. The first — the **shell** the render step is written in — was closed on 2026-09-15 by moving every value into the step's `env:` block, and `.github/tests` now refuses a workflow that interpolates a secret into a `run:` body. That fix stopped a secret being *executed*; it did nothing about the parser reading the file afterwards, and the workflow's own comment block says so.

It reaches seven secrets per stack — `ACME_EMAIL`, `POSTGRES_USER`, `POSTGRES_PASSWORD`, `POSTGRES_EXPORTER_PASSWORD`, `SLACK_WEBHOOK_URL`, `DEADMANSWITCH_URL`, `GRAFANA_ADMIN_PASSWORD` — and the rendered `GRAFANA_BIND_ADDRESS` with them. Two of the seven are values the operator does not choose: a Slack webhook URL and a dead-man's-switch URL are issued by their vendors, so "generate it from a safe alphabet" is not advice that can be followed for them. What stands in for a fix today is a sentence in three documents telling the operator to generate the other five with `openssl rand`, whose alphabets happen to avoid the characters that break — an instruction nothing enforces, that no check reads, and that says nothing about the two values it cannot reach.

## What Changes

- **Each value is escaped for the dotenv parser before it is written.** Every assignment is rendered as `NAME="<escaped>"`: the value is wrapped in double quotes, and within it `\` becomes `\\`, `"` becomes `\"` and `$` becomes `$$`, applied in that order. Measured against 72 values across both consumption paths — every character class the parser treats specially, in isolation and adjacent — this returns the stored value byte for byte in every case, altering none and being refused for none. A further 22 establish what the rendering it replaces corrupts and in which positions. `design.md` carries the measurement and the two renderings that were rejected; the harness that produced it is committed alongside, at `tools/env-rendering-probe/`, so the evidence can be re-taken rather than trusted.

- **The render step gains one choke point.** A `render <name> <value>` helper escapes and writes; the block below it is eight calls and nothing else. That replaces eight `printf` lines each carrying its own format string, and it is what lets a static check establish that no value reaches the file unescaped rather than checking eight lines individually.

- **The step reports, by name, each value the previous rendering was corrupting — and names no value.** Whatever was provisioned from such a value, such as the database role `initdb` created from `POSTGRES_PASSWORD` at that instance's first boot, is keyed to the corrupted form and stops matching on the deploy that fixes it. The notice is how an operator learns that before an authentication failure teaches them, and a notice reporting nothing is this change's evidence that nothing needed rotating. Which values those are was **measured** rather than assumed — rounds 5 and 6 of `design.md` sweep the current rendering and find five characters with a position in which it alters the value: a `$` anywhere, a `"` or an apostrophe opening the value, a `#` preceded by a space, and a line break anywhere, plus leading or trailing whitespace. The report covers those, detected by presence anywhere rather than by position, plus a backslash carried as a stated margin. Decision 9 records what the notice discloses, that its audience is wider than the secret store's, and why that trade is the right one at these values' entropy.

- **`.github/tests` gains a module asserting the render step's shape**: that every name written into `.env` is written through the helper, that the helper applies exactly those three substitutions in that order, that no line writes a value into the file by any other route, and that the set of values so written is **every variable `platform/.env.example` documents** — derived rather than a literal, so a ninth value added next month cannot pass by being absent.

- **Three documents that describe this gap as open are corrected**, and they are the reason this change touches prose at all: `platform/README.md`'s "two layers" section, the comment block above the render step in `platform-deploy.yml`, and `docs/backlog.md`'s own entry, which is deleted as the change archives. Each currently tells a reader that the `$` case is unshut and that single-quoting does not help. The first half becomes false with this change. **The second half was already wrong**, and the correction is stated rather than quietly dropped: single-quoting the *rendered line* does survive the parser for values carrying no `'` and no trailing `\`, and for the rest it makes Compose **refuse the file** rather than altering anything — it has no silent failure mode at all. What does not work, and what was measured, is re-quoting inside the **shell** layer, which is a different layer and was fixed differently. That mistake is why this entry read for a day as though no rendering could work. Double quotes with escapes are chosen over single quotes because a refusal withholds the deploy of a stack whose secrets are unchanged, for a value that may be vendor-issued and so unfixable — not because single-quoting corrupts, which it does not.

- **The standing `openssl rand` instruction stays, and stops being load-bearing.** It remains good hygiene and it is what the two vendor-issued values could never satisfy; it is no longer what stands between a secret and its service. Its citation is corrected while the paragraph is rewritten: `platform/README.md` and the backlog entry both send the reader to `docs/bootstrap-a-new-host.md` §0, and the commands are in §7.2.

- **`docs/onboard-an-application.md` stops instructing the defective shape.** §4.4 tells every application repository to render its own `.env` from secrets and ship it the same way, which reproduces this defect in each of them. The instruction gains the escaping rule and a pointer to the implementation here. §4.4's path is `env_file:` rather than interpolation, so the rule was measured on that path too rather than assumed to carry across — it does, and the one difference between the paths is recorded because it is what would have made that a wrong inference.

## Non-Goals

- **The layers after Compose's parser.** This change obliges what the parser *yields* for a name, which is the boundary its mechanism controls. Two of the eight values go somewhere else afterwards: `SLACK_WEBHOOK_URL` and `DEADMANSWITCH_URL` are interpolated into the content of an embedded Alertmanager **YAML** configuration, where a `:` followed by a space, a `#`, a quote or a newline would change or break the parse, and `ACME_EMAIL` becomes a Traefik `command:` argument. Nothing here measures or escapes for those contexts. Both URLs are vendor-issued and neither carries such a character today, which makes this a residual rather than a defect — and `design.md` Decision 7 records that this is the same species of reasoning Decision 1 refuses to accept as a discharge, so it is written down as work rather than as an argument that nothing is owed.

- **Making the corrected value reach a container that is not replaced.** *A Shipped Configuration Change Is Visible to the Container Runtime* (`openspec/specs/iac-platform-deploy-pipeline/spec.md`) states that changing a value an embedded configuration interpolates moves no committed text and therefore replaces no container. So for the two alert URLs, a corrected rendering ships and Alertmanager keeps the old value until something else replaces it. This change does not alter that requirement or work around it; it names the interaction, and the effect observation includes a deliberate replacement so the observation cannot pass on a fix that is still inert.

- **Verifying at deploy time that what was rendered is what the host's Compose parses.** The escaping rule is measured here against Compose v5.4.0 on the authoring workstation and the production host runs v5.5.0; nothing in this change detects a future Compose that changes the rule, and this repository has no test tier that may run a container to find out — `.github/tests` is forbidden one by its own constraints, and Molecule's subject is an Ansible role. `design.md` Decision 6 states the residual and this change records a backlog entry for the check that would close it.

- **Refusing a secret that contains a special character.** Considered, and it is the shape the current documented instruction implies. Rejected: it would fail the deploy of a stack whose secret was accepted yesterday, and two of the seven values are issued by a vendor rather than chosen, so a refusal has no remedy an operator can perform. Escaping makes the question not arise.

- **The check that refuses a secret built into a URL.** `assert-no-secret-is-built-into-a-url` is a separate backlog entry with its own reasoning about which names count as secrets, and it reads the same render step this change rewrites. It is left alone deliberately: folding it in would put a check whose three previous drafts each failed review inside a change whose own subject is a one-function fix. The `env:` block that check will read is left exactly as it is, so nothing here moves the ground under it.

- **Fixing the application repositories' deploy workflows.** `commerce-ops` and every application copied from it render `.env` the same way and carry the same defect. Those workflows live in repositories this one has no authority over; what is in scope here is the instruction that produces them.

- **Rotating a secret.** Rotation is not performed by this change and no value in any Environment is altered by it. It is **not** assumed unnecessary, which is the difference from how this Non-Goal read in the first draft: whether any current value was being corrupted is established by the notice described above, on the first deploy, rather than argued from the alphabet the generated values come from. Where the notice names one, rotating it — and re-provisioning whatever was derived from its corrupted form — is a follow-up with its own steps, and `design.md` Decision 9 says why it cannot be waived by reasoning about how the values were generated.
