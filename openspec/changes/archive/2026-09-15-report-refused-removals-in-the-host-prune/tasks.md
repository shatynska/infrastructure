## 2. The script counts and names refusals

- [x] 2.1 In `ansible/roles/image_prune/tasks/main.yml`, capture each `docker image rm` invocation's **exit status** alongside the output it already reads, in both removal paths — the by-identity path and the per-tag loop. The non-failing guard must stay, since `set -e` is in force and a rejected removal is a normal outcome, but **`|| true` must become `|| rm_status=$?`**: written as `rm_output=$(docker image rm … 2>"$inspect_err" || true)` the guard sits *inside* the command substitution, so the assignment's status is unconditionally zero and the rejection is unreadable. The form is `rm_status=0; rm_output=$(docker image rm … 2>"$inspect_err") || rm_status=$?` — still guarded, capturing instead of discarding, and writing into the **existing** single-slot temporary file rather than a second one (task 2.3). An implementation that keeps `|| true` ships a `refused` pinned at zero, which is the signal-free report this change exists to remove, printed in a third field. Keep the `Deleted:` read exactly as it is: `removed` is specified as the count of invocations that reported the image deleted, and a zero exit does not establish that — the untag-without-delete path has one
- [x] 2.2 Add a `refused` accumulator beside `removed`, incremented once per **identity**, not once per invocation, and only where no invocation for that identity reported the image deleted. `design.md` Decision 2 is the precedence rule: an identity both deleted and rejected counts as removed, so that `removed + refused` cannot exceed `considered`
- [x] 2.3 Capture the rejected invocation's stderr and emit one line per refused identity, naming the identity and the runtime's own message, to **standard error**. Reuse the existing single-slot `inspect_err` temporary file and its trap rather than adding a second one — it exists for exactly this purpose and its comment already says why one message at a time is the point — and use that one name in both removal paths, since two names for one slot is how a second untrapped temporary file gets created. Widen the variable's own comment, which currently says it holds one `docker image inspect` stderr at a time: it will hold a removal's too. Strip newlines from the captured message the way the unresolvable-reference path already does, so one refusal is one journal line

## 3. The refusal fixture's registry half

**The fixture is split across two files and the split is the point.** The registry half is fixture code and belongs in `converge.yml`, which is this section. The host half — pulling the identity back by digest, so that the host acquires something refusable — belongs in the `verify.yml` arrangement step and is section 1's, because *when* the host acquires it is what makes both new counting scenarios assertable rather than only one. Built wholly in `converge.yml`, the identity is refusable from the first run onward and *A run whose removals were all performed reports no refusals* has no run in this role's suite to assert against.

- [x] 3.1 In `ansible/roles/image_prune/molecule/default/converge.yml`, build one further image with a marker of its own — distinct content, so that it is a distinct identity from every existing fixture and in particular from the digest-pin fixture, which is **kept** and would make the new one a non-candidate if they collided — and tag it into two repository paths under the local registry
- [x] 3.2 Push both references, then remove every local reference to that identity, so that the **registry** holds it under two repository paths and the host holds no image for it at all. Dropping the two build tags **by name** is sufficient and is the form to use: a push gives the identity a `repo@digest` reference in each repository, and removing a repository's last tag drops that repository's digest reference with it, so the second removal deletes the image. Do **not** remove by identity — `docker image rm <id>` on an identity carrying two repository references is the very rejection this fixture exists to produce, so a cleanup written that way fails on its own subject
- [x] 3.3 Assert the result as the step's own premise: `docker image inspect` on that identity must fail. This guards a property of the runtime rather than a known defect in the cleanup — what it catches is a later edit leaving a reference behind, which reintroduces the whole-in-converge placement through the back door. Two references surviving makes the first run's by-identity removal rejected and fails the `refused 0` assertion loudly; one surviving makes the first run delete the identity, which costs nothing because the arrangement re-pulls it. Neither is silent, which is why this is an assertion rather than a more elaborate cleanup
- [x] 3.4 Record both digest references in `/var/tmp/image-prune-fixtures.env` alongside the existing entries, so the arrangement step has something to pull. Do **not** record an identity here — the host does not hold one at this point, and the identity the arrangement step observes after pulling is what section 1 asserts on
- [x] 3.5 The registry's readiness probe is the existing push loop, and this fixture's pushes come after it, so they need no probe of their own. Confirm that rather than assuming it — if the new pushes are placed before the seed push, they become the readiness probe and its failure message stops naming the right thing
- [x] 3.6 Comment the fixture with what it is for, in the register the file already uses: why the host deliberately ends the converge holding nothing of it, what would pass for the wrong reason if it were built differently (one reference, or a surviving tag), and that once pulled back the identity survives its own removal attempt by design
