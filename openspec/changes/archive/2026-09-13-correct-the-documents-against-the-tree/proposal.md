## Why

Four archived renames and one obligation that was never written into the runbook have left this repository's own documents saying things that are not true of the tree. The reader who pays for it is the one the runbook is written for: someone cloning this repository to stand up a company's hosts, reading `docs/bootstrap-a-new-host.md` straight through and following it. One of the defects makes a documented step fail outright; the rest read fluently and are wrong.

One class of the rot is invisible to every check this repository has, and that is what makes this more than a sweep. A citation naming a **requirement** is correct when it is written, correct when it is reviewed, and wrong only once a later change renames that requirement — which is word for word the argument the *Source Files Cite Specifications by Path and Changes by Name* requirement (`openspec/specs/iac-repo-foundations/spec.md`) already makes for the pre-archive **path** form it does assert. The path half is checked and the name half is not, and the measurement below is what that asymmetry has cost: `docs/change-queue.md` entry 74 recorded three instances of one retired name, and a sweep for the predicate rather than for the reported rows finds **47 occurrences to correct across 13 files**, plus one legitimate occurrence in `docs/deferred-work.md` that records the retirement itself.

## What Changes

- **Sweep every retired requirement name from committed files outside `openspec/`.** Measured on 2026-09-13 against trunk `80a8ec5`: *Each Environment Declares Its Own Pipeline Configuration* in seven files, *Each Environment Has a Dedicated Hetzner Cloud Project* in four, *Dynamic Inventory via hcloud Plugin* in three, *Environment and Module Folder Structure* in two — thirteen files in all, three of which state the name only across a comment's line break, so a per-line reader finds nothing in them. A fifth, *Dedicated Hetzner Cloud Project for Prod*, appears once in `docs/deferred-work.md` as a record of its own retirement, and is exempted rather than swept.
- **Add the check that makes the requirement-name half of the citation rule enforceable**, a `.github/tests` module in the idiom of `test_the_external_service_names_are_retired.py`. Its retired-name set is **derived from the archive** — every `### Requirement:` under a `## REMOVED Requirements` heading in an archived delta spec, less every name that currently exists — rather than hard-coded, so it needs no edit when the next rename happens. This is the judgment entry 74 says the change owes; entry 74's other candidate check, over citations naming a **change**, is declined on measured evidence and recorded instead.
- **Correct the remaining stale names entry 74 names**: `README.md`'s stack folders (`prod` and `staging` → `main-production` and `main-staging`), the two citations of a change named `add-a-staging-stack` that never existed, `main-data` in the `swap` role's defaults and README, and the heartbeat check `<company>-prod alertmanager` in §7.1 — the last of which needs a step at the observer as well as an edit here, since the check already exists under the old name.
- **Name the converge keypair for its stack** (`docs/change-queue.md` entry 73): `~/.ssh/<company>-ansible-ci-<environment>` → `~/.ssh/<company>-ansible-ci-<stack>`, at the four lines that hold the literal, in §0.3 and §6.6, with Appendix A's converge-key row reviewed — it names the secret rather than the filename and may need no edit. It is the last per-stack artefact in this repository still named on the environment axis.
- **Correct the dead `docs/change-queue.md` pointers** that survive as live forward-references rather than as history: Appendix C's entries 21, 22 and 26 (two delivered, one declined into `docs/deferred-work.md`), `docs/deferred-work.md`'s `**Owner:** … entry 62`, and entry 23 as cited by `ansible/roles/platform_data_volume/tasks/main.yml`, `ansible/roles/swap/tasks/main.yml` and queue entries 25 and 30.
- **Add the GitHub App to the bootstrap document.** `APP_CLIENT_ID` and `APP_PRIVATE_KEY` appear nowhere in `docs/bootstrap-a-new-host.md` — not in §3.3's secret table, not in Appendix A, which calls itself "Every credential the system uses, in one place", and not in stage 9. A clone following the document verbatim reaches stage 9.4, dispatches `pre-commit-autoupdate.yml`, and the run dies at *Mint a token for the App*. The App is user-owned on a personal repository, so a company clone must create one of its own. This is the one defect here that makes a documented step fail rather than merely read wrong, and the obligation it discharges is already specified — *Automated Dependency Updates* (`openspec/specs/iac-safety-hardening/spec.md`) requires the separate, repository-scoped, non-expiring identity and says why.
- **Leave the thirty stale scenario-title citations to a change of their own**, recorded rather than swept. A citation names a requirement and often a scenario inside it; both halves rotted in the same renames, and the second is a different predicate with thirty instances whose replacements are not mechanical. The artifacts say so rather than implying the citations are whole afterwards.
- **Rewrite the banner in `docs/naming-conventions.md`** to say what is actually outstanding. It claims the scheme is "NOT YET IN EFFECT" and that "75 alone remains", over a tree where every name the scheme governs has moved except the two GitHub Environments, and where entries 73 and 74 are outstanding beside 75.

## Capabilities

### New Capabilities

None.

### Modified Capabilities

- `iac-repo-foundations`: *Source Files Cite Specifications by Path and Changes by Name* gains the obligation that a requirement named in a citation SHALL be one that exists in the specification cited, and that the obligation SHALL be asserted by the executable suite that gates every pull request — for the reason the requirement already gives about the path form, which applies unchanged to the name.

## Impact

**Documents corrected**: `docs/bootstrap-a-new-host.md` (§0.1, §0.3, §0.4, §2, §3.2, §3.3, §6.6, §7.1, stage 9, Appendix A, Appendix C), `docs/naming-conventions.md`, `docs/change-queue.md`, `docs/deferred-work.md`, `README.md`, and `AGENTS.md`'s citation section, which states only the path half of the rule this change extends.

**Source files corrected**: `terraform/stacks/main-staging/versions.tf`, `.github/workflows/apply.yml`, `.github/workflows/drift.yml`, `.github/workflows/pr-validation.yml`, `ansible/ansible.cfg`, `ansible/roles/swap/defaults/main.yml`, `ansible/roles/swap/README.md`, `ansible/roles/swap/tasks/main.yml`, `ansible/roles/platform_data_volume/tasks/main.yml` — every one a comment or a document string, none a change in behaviour.

**Tests**: a new module under `.github/tests/`, plus the existing modules whose asserted literals move with the comments they read — `test_terraform_stacks_are_the_iterated_unit.py` asserts the `versions.tf` comment line verbatim, and `test_a_second_environment.py`, `test_a_stack_and_its_environment_are_named_separately.py`, `test_environment_agnostic_pipeline.py`, `test_host_configuration_names_its_environment.py`, `test_host_converge_workflow.py` each name a retired requirement in their own prose.

**Queue and deferred work**: entries 73 and 74 are deleted from `docs/change-queue.md` in the archive commit, which is also what expires the temporary exemption that file needs while entry 74 still names a retired requirement. A new queue entry records the thirty stale **scenario**-title citations this change leaves; `docs/deferred-work.md` records the declined change-name check.

**Not in scope**: entry 75. Renaming the two GitHub Environments is unaffected by anything here, and §3.2 already tells a new deployment to name its own for its stacks — which is why this change can correct what the documents say without paying entry 75's price.
