**This change's subject is role behaviour, so Molecule is the mechanism that observes it** — the second row of this project's test table. Four of the delta's seven scenarios are static reads of committed files and belong in `.github/tests`; the other three are behaviour.

**The effect is invisible in host state, which is what makes the channel a design question rather than a detail.** A fetched index and an unfetched one leave exactly the same packages installed, so nothing on the host distinguishes them. `ansible.builtin.apt` returns `cache_updated` independently of `changed`, and that return is the only place the distinction exists — so the role's apt tasks are registered and the **assertions sit in the same play as the invocation they characterise**. Registers do not cross plays: Molecule runs converge and verify as two separate `ansible-playbook` invocations, which this repository states in its own comment in `image_prune`'s `absent-heartbeat-key` converge. So 1.2 and 1.3, which characterise the **converge's own** role run, assert in `converge.yml`; 1.4, which characterises an invocation the test itself makes, asserts in `verify.yml` beside it. A marker file would bridge the gap and is refused for its own reason: its content differs between the converge and the idempotence run, so the task writing it reports `changed` and breaks the idempotence check this change is otherwise careful to preserve. `design.md` Decision 6 carries the full reasoning.

**Assert the rule, not the run.** Molecule runs the converge play twice — converge, then idempotence — and on the second run the first apt task *correctly* does not fetch, the index being minutes old. An assertion reading "the first task fetched" fails against a correct implementation on that pass. What holds on both runs is the requirement's own sentence: a task fetches exactly when the recorded fetch time is outside the bound.

**Section 1 comes first on purpose** — the tests are derived from the delta before the implementation exists.

**This change depends on `narrow-the-molecule-trigger-to-what-it-reads`**, which writes `docs/change-queue.md` entry 65 — this change — along with 66 and 67. **Observed 2026-09-11: that change merged as pull request #142, and this branch has been rebased onto that merge**, so entry 65 — this change — is present here and the numbers resolve. ## 1. Derive the tests from the delta

- [x] 1.1 In `ansible/roles/hardening/molecule/default/converge.yml`, add a pre-task recording the instance's **last-fetch time** before the role runs — the mtime of `/var/lib/apt/periodic/update-success-stamp`, falling back to `/var/lib/apt/lists`, and to **the epoch where neither exists**, which is the module's own third branch (`cache_time = 0`) and the case the delta's never-fetched scenario turns on. `stat` reports a missing path as `exists: false` rather than failing, so all three branches are expressible in one pre-task. This is the antecedent every assertion below is stated against, and recording it before rather than reasoning about it afterwards is what makes them hold on the idempotence pass. **Record the instant of the comparison alongside the mtime**: the assertion runs minutes after the module made the same comparison, index age only grows, and a recorded time within minutes of the bound at role-run time can be outside it by assertion time. Unreachable in a `molecule test` sequence, where the ages are months or minutes; reachable in a hand-driven re-converge, which is exactly when someone would be debugging.
- [x] 1.2 Establish *A second install task in the same converge does not re-fetch*: in the same play, after the role, assert the **second** role apt task reported `cache_updated: false`. True on both runs and the change's central claim. Pair it with the presence half by leaning on the scenario's existing UFW and fail2ban assertions rather than inventing one — `ansible.builtin.apt`'s return carries no presence field, and `package_facts` would be a second mechanism for a thing already asserted.
- [x] 1.3 Establish *An install on a host with no record of a fetch still fetches*: assert the **first** role apt task's `cache_updated` equals whether 1.1's recorded time was outside **the role's own bound variable** — not the hour `design.md` Decision 2 chose. The assertion is self-referential on purpose: the delta makes no normative claim about the value, so nothing here guards the default, and stating that plainly is better than implying a check that does not exist. **The role's variable is in scope for this assertion only because `converge.yml` invokes the role through `roles:`**, which exposes its defaults to the play; under `include_role` it would need `public: true`, and without it the assertion fails on an undefined name that points at the expression rather than at the cause — the shape this capability's *absent required input is reported by name* requirement exists to avoid. On the first converge that time is the image's build date and the task fetched; on the idempotence run it is minutes old and it did not. - [x] 1.4 Establish *An index older than the bound is refreshed* **in `verify.yml`, on the role invocation that is already there** — not by adding one to the converge play. Immediately before that invocation, set the index's recorded fetch time to outside the bound; then assert its first apt task reported `cache_updated: true`. Without this assertion a change that simply stopped fetching would pass everything else here, so it is what makes the bound a bound rather than a disabling.

      **Placement is not a matter of taste, and the obvious choice is a trap.** A bound-overridden invocation in the converge play costs four fetches, not one: Molecule runs that play **twice**, and the bound is a single variable per role, so both apt tasks fetch on both passes. That returns four of the six fetches this change exists to remove, in the very scenario every figure in `design.md` is computed from. `verify.yml` runs **once**, after the idempotence pass, and already carries a third role invocation for the web-CIDR path — `converge.yml`'s own header records that it was kept out of converge precisely to keep the idempotence check scoped to one state. Reusing it costs one fetch and touches neither the idempotence check nor that header's claim.

      **Back-date by removing the *contents* of `/var/lib/apt/lists` and then setting that directory's mtime to a fixed far-past timestamp, in that order.** Two details, each of which turns a fixture error into something that reads as a broken mechanism. The order: deleting the contents sets the directory's mtime to *now*, which reads as fresh and skips — so back-date after emptying, never before. And the directory itself must survive, along with its `partial/` subdirectory: removing and recreating it loses the mtime the fixture is setting, and a missing `partial/` makes apt fail with `E: List directory /var/lib/apt/lists/partial is missing`, which names apt rather than the fixture. And the choice of path is not free either — `design.md` Decision 1 records why the other two forms fail. Do **not** back-date `/var/lib/apt/periodic/update-success-stamp`: `get_cache_mtime()` prefers it, `cache.update()` never writes it, so it would pin the read value in the past and every later task would report `cache_updated: false` however much it fetched. Do not back-date the lists directory without emptying it either: `cache_updated` is true only where the mtime **moved**, and a re-fetch that resolves entirely to *not modified* writes nothing and moves nothing.

      Back-dating rather than overriding the bound is deliberate, and the claim for it is narrow: `verify.yml` includes the role without `public:`, so the role's bound variable is not in scope for a task placed before it and the back-date distance is a literal. It therefore catches an **absurd** default — one longer than the distance chosen — and not a merely wrong one. Nothing here guards the default's value, as 1.3 also says.

      The back-dating task sits in `verify.yml`, so whether it reports `changed` is irrelevant to Molecule's idempotence check, which re-runs `converge.yml` alone — which is why this placement escapes the objection a back-dating fixture would face in the converge play.
- [x] 1.5 Establish three scenarios in `.github/tests`, as static reads of committed files. First the **positive** obligation, which nothing else covers: a qualifying own-role apt task — unpinned, not installing from a source written earlier in the same file — that declares **no** bound fails. Without it the requirement regresses silently in the one direction the change exists to establish, and `image_prune`'s single bound is asserted by nothing at all. Then the two refusals — *A pinned-version install declares no bound* and *An install from a source the same run added declares no bound*: a task naming an exact version, or installing where an earlier task in the same file writes a destination under `/etc/apt/sources.list.d/`, and also declaring a bound, fails. **Key the second on the destination, not on the module**: this repository's only instance writes its source with `ansible.builtin.get_url`, so a check looking for `apt_repository` matches nothing and passes vacuously — a green check establishing nothing. **Enumerate the roles from committed content, or exclude the Galaxy-installed role by name** — `ansible/roles/geerlingguy.docker/` is gitignored, so a bare glob over `ansible/roles/*/tasks/` sees it in a provisioned working tree and not in continuous integration, and a check that disagrees with itself between the two is worse than no check. State in the docstring that the same-run-source rule reaches a source written in the same file and not one written by another file or an earlier role, so the bound of the check is recorded rather than assumed.
      **The check found a pre-existing defect while being written**, recorded as `docs/change-queue.md` entry 68 rather than fixed here: `TestEveryComposeFileDeclaringAServiceImageIsCovered` walks the tree without pruning `.molecule-home/`, so it is green in continuous integration — where Molecule is never provisioned — and red on any developer machine that has followed this project's own Molecule instructions. It is the same class this task guards against, on a walker that predates this change.
- [x] 1.6 Establish *The bound is a variable, not a literal per task* and *A test fixture play is not held to the bound* in the same module, under **the same role enumeration 1.5 uses** — its globs reach `ansible/roles/*/tasks/` and `ansible/roles/*/molecule/*/` the same way, and the gitignored Galaxy role carries a scenario with a literal `cache_valid_time`, so a check without the exclusion disagrees with itself between a provisioned tree and continuous integration: the role task files take the bound from a role variable and a literal fails, while `ansible/roles/*/molecule/*/prepare.yml` is outside the check entirely.
