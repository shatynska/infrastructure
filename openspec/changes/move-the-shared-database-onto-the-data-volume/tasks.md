**Which pull request carries what, because the split is not free.** The first carries the host directory and the planning artifacts and nothing else. Everything that *asserts* the new arrangement — the Compose bind, the static assertions, the documents — goes in the second, with the change that makes those assertions true. An assertion written against a bind source the tree does not yet declare fails `pr-validation.yml`'s required run of the static suite, which would make the first pull request unmergeable and, if forced through, leave the trunk red for every other pull request in flight. The cost of the other order is that the first pull request lands an inventory entry with no assertion behind it for the length of the window; that is bounded by this change's own life, where a red trunk is not.

**Who writes what in section 3.** Tasks 3.1 to 3.3 re-point assertions that already exist at a store whose spelling moves, and are the implementer's. Tasks 3.4 and 3.5 assert properties that are new, so they are the derived-test author's — they trace to the deltas, not to the code.

**A stated exemption from the order that author normally works in, because the split makes it unachievable.** This project's workflow has the derived tests written before the implementation they cover. Both pull requests come off one branch, so anything committed before the first merges is *in* the first — and 3.5, and 3.4's Compose half, are red against that tree by construction, which is the whole reason section 3 sits in the second pull request. So section 1 is implemented and merged before the tests that cover it exist. **Reason:** the derived tests trace to the approved deltas rather than to section 1's inventory entry, and the alternative — committing an assertion the tree cannot satisfy — makes the first pull request unmergeable and the trunk red for every other pull request in flight. 3.4's `group_vars` half could be authored with section 1 instead, and is not, so that the agreement it asserts is written once against both sides rather than twice.
