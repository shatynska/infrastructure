- [ ] 5.2 Establish — not assume — that staging can pull the application's image, before any deploy is attempted, and **do it as `root`**: the converge authenticates *root's* Docker credential store (`deploy_user`'s task is named for it), and the same `docker pull` run as `ops-claude` resolves that account's own store, which nothing ever authenticated. So `ssh -i ~/.ssh/shatynska-root root@100.85.219.36`, then `docker pull ghcr.io/<org>/commerce-ops:<a tag that exists>`. None of the three outcomes blocks this change's gate at 5.1: it works, and stage 8.2's fourth step is discharged; it is denied, and either `ghcr_pull_token` never reached the host — the converge log's "Report that GHCR authentication was skipped for want of a credential" task is what tells that from a credential the registry refused — or the credential cannot read this particular package; or it was run as the wrong account, which is the failure this task exists to stop you from misreading as the other two. A success is only informative if the package is private, which is the case `ghcr_pull_token` exists for. The reason to look now is that otherwise it surfaces at `docker compose pull` in the other repository's pipeline, far from anything that would explain it.
- [ ] 5.3 The end-to-end observation is **not this change's gate** — the application cannot serve a request before its database exists, which is `provision-commerce-ops-database-in-the-shared-instance`, and it deploys from a repository this one does not touch. Recorded here so the route is not re-derived: from a session on the host, not from a tailnet device, `curl -k -I --resolve '<hostname>:443:127.0.0.1' https://<hostname>/`. Loopback is the one interface UFW does not filter; `https` because the `web` entrypoint redirects unconditionally; `-k` because no certificate can issue while 443 is closed and Traefik answers with its own default one; `--resolve` rather than an IP literal so the request carries the name in SNI as well as in `Host`. A `404` from Traefik means the router is not there; the application's own status means it is.
