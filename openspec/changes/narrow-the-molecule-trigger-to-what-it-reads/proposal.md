## Why

The Molecule suite is triggered by `ansible/**` and runs every role's every scenario whenever any file under that directory changes. Most of that directory is not something any scenario reads. Of the twenty pull requests merged before this one, six touched `ansible/` and two touched a role; the other four changed an inventory source, a `group_vars` file, or `.envrc.example`, and each started seven containerised jobs verifying roles their diff did not touch. PR #137 and PR #140 did the same on 2026-09-11 — #140's entire `ansible/` footprint is `ansible/playbooks/host-baseline.yml`, which no scenario reads.

That was survivable while the suite cost ten minutes of wall clock. On 2026-09-11 it stopped being survivable: from roughly 06:00 UTC the Ubuntu archive became slow to reach from a hosted runner, and `apt-get update` inside a scenario's container went from 13 seconds to 309. The `image_prune` job, which had run between 9.1 and 11.5 minutes on every run for two days, took 74.5 minutes on PR #137 and comparable on PR #140. The runner image was identical across all three runs, and neither pull request changed a role, a scenario, the pinned toolchain, the Galaxy manifest or the runner script. A degraded upstream is not this repository's to fix; paying for it on pull requests the suite has nothing to say about is.

**The narrowing is not currently safe, and that is the more interesting half of this change.** Three tasks inside two Molecule verify plays are not verifying host state at all — they are static scans of committed files, delegated to `localhost`:

- `ansible/roles/deploy_user/molecule/default/verify.yml` greps the **whole repository** for GitHub and GHCR token markers.
- The same file scans **every `*.y*ml` in the repository** for a `ghcr_pull_token` assigned a committed literal, reading folded scalars across continuation lines.
- `ansible/roles/ops_user/molecule/default/verify.yml` greps `ansible/inventory/` for private-key markers, and its own comment says the scan is *derived* — "no scenario names that path, but it is where `ops_user_accounts` and therefore the committed key material actually lives".

Those three are the reason the trigger cannot simply be narrowed: excluding `ansible/inventory/**` would stop the third from running on precisely the pull requests that edit the files it exists to watch. They are also in the wrong place already, and by this repository's own rule. `AGENTS.md` says `.github/tests` is where a property that is a static read of a committed file belongs, and that it "is this repository's only mechanism that reads committed files at repository scope". A repository-wide token scan that only runs when `ansible/` changes is not covering the repository. What that costs is narrower than it first looks and still real: `gitleaks` already runs on **every** pull request, ungated by path, so a token pasted under `terraform/` is not unscanned. What these three add beyond it is a structural rule `gitleaks` has no equivalent of — a `ghcr_pull_token` assigned a committed literal, read across a folded scalar's continuation lines — and a read of the tracked tree rather than of the diff, which is what catches content that is already committed. Both of those are today confined to the pull requests that happen to touch `ansible/`. Moving them is what makes the narrowing safe, and it widens that coverage on the way.

## What Changes

- **Three static repository scans move out of Molecule verify plays and into `.github/tests`**, where they run on every pull request unconditionally rather than only on those that change `ansible/`. The two token scans keep their repository-wide root; the private-key scan is **widened** from `ansible/inventory/` to the same root, because a scan rooted at one directory while its siblings scan the repository claims a scope its root does not give it — the same argument this change makes against leaving them in the suite at all. What each matches is unchanged, and the `ghcr_pull_token` scan's continuation-line reading is the part that must survive the move intact, since a line-oriented reimplementation would pass over both scenario files that assign the token as a folded scalar.

- **The scans read the repository's tracked files.** `.github/tests` runs on developer machines as well as runners, and a working tree holds what a checkout does not — caches, virtual environments, sibling working trees, and the gitignored `ansible/.envrc` where a real GHCR token legitimately lives. A naive walk fails on those, and the remedy reached for is a path-exclusion list, which permanently blinds the scan wherever it is applied. Tracked files are also what `AGENTS.md` already says this suite's subject is. Where that enumeration is unavailable the assertion **fails rather than skips**: for a credential scan, a skip reports success for something nothing examined. Exactly one scan *widens* — the private-key one, from `ansible/inventory/` to every tracked file. The token-marker scan keeps the repository root it already had, and the `ghcr_pull_token` scan keeps its YAML restriction, which is its subject rather than an optimisation; both merely gain a defined file set in place of a filesystem walk. During planning, the token-marker pattern and the private-key pattern were each run over all 448 currently tracked files and matched nothing, so the widening introduces no pre-existing failure to clear.

- **The `ansible-verify.yml` change filter stops naming `ansible/**` and starts naming what the suite reads.** The polarity is an exclusion list, not an inclusion list: the filter matches `ansible/**` minus the paths established here as unread, so a path added under `ansible/` later runs the suite by default rather than silently skipping it. The excluded set is `ansible/inventory/**`, `ansible/playbooks/**`, `ansible/requirements.txt` and `ansible/.envrc*`.

- **The lint tier is untouched and is the answer to what covers the excluded paths.** `ansible-lint` and `ansible-playbook --syntax-check` remain triggered by `ansible/**` in `pr-validation.yml`. A change to `ansible/playbooks/host-baseline.yml` is still linted and syntax-checked on the pull request that makes it; what it no longer does is converge seven roles in containers. The two tiers were always distinguished by cost, and this change makes the cheap one carry the paths the expensive one cannot speak to.

- **The gate's structure is untouched, and its wording is not.** Discovery's vacuity refusal is already computed unconditionally and read before anything else, so narrowing the filter changes which diffs reach the "skipped, and correctly so" branch without adding, removing or newly exposing a branch. What must change is that branch's message: *"Nothing under the configuration directory changed"* becomes false once something under `ansible/` can change and be excluded, and it is the sentence a reader reaches for when working out why the suite did not run.

- **A check on the premise, not only on the filter.** The exclusions rest on a sweep establishing that no scenario reads those paths. That premise is what will rot, so `.github/tests` gains an assertion over scenario text itself: no controller-side read in an authored scenario may reach outside the paths this change enumerates. It is built on every route to the controller rather than on delegation alone, and it closes by refusing an unrecognised construction rather than passing over it. That breadth was earned the hard way: the first version of this design keyed on delegation plus a path spelling and missed two live reads, and a later version still omitted task-and-play inclusion, missing three more — `platform_data_volume`'s scenario reads its sibling's `converge.yml`, `prepare.yml` and `verify.yml` through `import_playbook`, carrying no delegation at all. A filter assertion would have caught none of the five; this does.

## Non-Goals

- **Per-role selection — running only the roles a diff touches.** Tempting, and materially harder than it looks: `image_prune`'s scenarios converge `docker`, and `ops_user`'s default converges `docker` and `deploy_user`, so a correct per-role matrix needs the reverse closure of a dependency graph derived from scenario text. Deriving that graph wrongly loses coverage silently, which is the failure mode this repository's pipeline is built to refuse. Recorded as its own queue entry. This change takes the whole of the safe win — the four-in-six of recent pull requests that touch no role at all — and leaves the contested remainder.

- **`cache_valid_time` on the roles' `apt` tasks.** It would cut `hardening` from six full index fetches per job to one, and on 2026-09-11 it would have helped more than anything here does. It changes role behaviour on a production host, not only in a container, and it changes what the idempotence pass exercises. Queue entry 65.

- **`timeout-minutes` on the Molecule matrix.** Worth having, and orthogonal: the runs that prompted this change were slow, not hung, and a timeout tight enough to catch a hang would have failed both pull requests over a degraded mirror. Queue entry 66.

- **Relocating the controller reads that stay inside the paths the suite is triggered by.** Nine reads plus one declaration: `deploy_user`'s and `ops_user`'s private-key scans over their own role directories, `ops_user`'s README assertion and its nested `ansible-playbook`, `swap`'s `defaults/main.yml` lookup, `docker`'s `ansible/requirements.yml` lookup, `platform_data_volume`'s three `import_playbook` reads of its sibling scenario's files, and every scenario's `ANSIBLE_ROLES_PATH`. All reach paths that remain triggers. They are left where they are — but they are **enumerated**, in `design.md` Decision 1, because the standing check above refuses any controller read not on that list.

## Capabilities

- `iac-cicd-pipeline` — MODIFIED. Two requirements: the Ansible verification requirement, whose trigger clause is what this change narrows and which gains the obligation that the suite not be the sole mechanism verifying a repository-scope static property; and the self-verification requirement, which gains the corresponding home for those properties.

## Impact

- Changed: `.github/workflows/ansible-verify.yml` (the filter, and the aggregating job's correct-skip message — discovery is **not** edited: its vacuity refusal is already independent of what the diff selected, and the delta's clause saying so states existing behaviour rather than requiring a change), `.github/tests/test_ci_configuration.py` (the extracted resolution and gate bodies are already executed standalone there, and the filter's excluded set becomes an assertion of its own), `ansible/roles/deploy_user/molecule/default/verify.yml` and `ansible/roles/ops_user/molecule/default/verify.yml` (three tasks and their assertions removed, with the reason recorded in place).
- New: the relocated scans, in `.github/tests`.
- Also: `docs/change-queue.md` gains entries 65 (`cache-the-apt-index-within-a-converge`), 66 (`bound-the-molecule-matrix-with-a-timeout`) and 67 (per-role selection), recorded outside this change because a note kept inside one is archived with it.
- No repository setting changes. The registered required status check keeps its name and its shape; what changes is when its matrix has rows.
- **The branch and the working tree are removed after this change's record pull request merges**, once every other pull request it opened has merged — read from each pull request's own state rather than from branch ancestry — and nothing uncommitted or unpushed remains. The working tree is removed from the repository's main working tree rather than from inside the tree being removed, and this tree's Molecule namespace goes with it; `ansible/scripts/run-molecule destroy --all` from each role directory precedes that, and `docker ps` is worth a look afterwards rather than taking this record's word for it. Recorded here in prose because both steps happen after the commit that writes `tasks.md`, so a task for them could never be ticked in the file that contains them.
