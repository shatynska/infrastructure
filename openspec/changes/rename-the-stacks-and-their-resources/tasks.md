## 10. The operator's out-of-band steps, immediately before the merge

These are outside this repository and no plan proves them. They are tasks because the change does not work without them.

**They are due between the pull request's approval and the merge, not before the pull request.** From the first of them until the apply lands, every converge and every platform deploy fails: the old tailnet name no longer resolves and the new server name is not yet in Hetzner. An earlier draft of this list placed the whole section ahead of task 9.2, which would have held that window open across code review, plan review and the required-reviewer wait — a wait entry 61 measured as long enough for HCP's state serial to move under it. Doing them *after* the apply is worse and is what this ordering exists to avoid: continuous integration would be broken with only the operator able to end it, and nobody watching for the moment it started. Design.md decision 6 is the reasoning and the measurements behind it.
