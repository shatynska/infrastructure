## Departures worth recording

- **6.5 was performed through a privileged container rather than `sudo`.** The task named `sudo losetup -d`, which needs an interactive password this session has no way to supply. A privileged container writes the same kernel loop table — that is the whole reason the minors leak across containers in the first place — so the operation is identical rather than a substitute for it. Each of `/dev/loop87` through `/dev/loop91` was confirmed to still name a `platform-data-volume-*.img` backing file before being detached, and the same attribution rule the fixtures use guarded the sweep: anything else would have been reported and left alone.
- **3.7's premise assert shipped as `failed_when: rc != 2`, not the `rc == 0` the approved plan named, and 3.3 is affected with it.** 3.7 says the assert fails when `blkid` returns 0; 3.3 says the two `superseded-path-*` plays gain neither a detach nor a premise assert. Both were true when written and both stopped being true in `build`'s third review round, which found that `rc == 0` reads *every* non-zero code as "no filesystem" — so a `blkid` that never probed reported the premise satisfied, in the assert whose own comment says that failure is invisible from inside the container. Measured in the pinned image (and independently re-measured by the reviewer, on util-linux 2.37.2, agreeing on all four): unformatted 2, formatted 0, usage error **1** — not the man page's 4 — and absent device 2. `rc != 2` accepts only "looked, found nothing". It was applied to all four plays including the two 3.3 says are untouched, because two failing closed and two failing open is worse than either regime. The task texts are left as approved; this is the record of what actually shipped.
- **2.1's derivation shipped as `* 16`, not the `* 8` the approved plan named.** The task text is left as approved rather than rewritten to match the code, because what it records is what was decided at `plan`. The slot widened during `build`'s review, for a reason the plan could not have anticipated: the same review's finding that the two `multiple-devices` arms must take separate pairs raised the offsets in use from five to seven, leaving one spare in an eight-wide slot — nearly exhausting the headroom `design.md` Decision 3 gives as the whole reason for sizing the slot above what is used. Sixteen restores it; the new ceiling, `1024 + 4095*16 = 66544`, was verified to associate and detach cleanly in the pinned image alongside 66559 and 66560. `design.md` Decision 3 and Decision 7 carry the reasoning; this note is what connects them to a task that still says eight.
- **2.1's `shellcheck` clause is satisfied only up to a pre-existing warning.** `shellcheck ansible/scripts/run-molecule` reports SC2088 (`Tilde does not expand in quotes`) at the literal-tilde `case` pattern in `collections_path`. It is present at the merge base `4ad4add`, is untouched by this diff, and is deliberate — the pattern matches a literal `~/` prefix rather than expanding one. The task's wording says "clean", which is not true of the file and was not made untrue by this change; recorded here rather than left to read as a claim this change established.
