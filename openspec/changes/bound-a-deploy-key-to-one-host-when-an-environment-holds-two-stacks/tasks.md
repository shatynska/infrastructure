## 6a. What the second code-review round changed

Recorded here rather than folded into the tasks above, because these are corrections to work those tasks had already reported as done -- and one of them is a defect in a check this change itself introduced.

**The guard on this change's central invariant was defeated by editing a key's comment.** `duplicate_public_half_offences` and `shared_key_offences` bucketed on the whole `public_key` string, comment field included, so two hosts authorising **one private half** under two comments were not reported. Measured before the fix: byte-identical duplicates were caught, the same material under two labels returned `[]` from both functions. What makes it live rather than theoretical is that `docs/onboard-an-application.md` instructs a distinct per-target comment -- so when a second tenant's file is produced by copying an existing one, relabelling is the one edit a careless operator reliably makes, and it was precisely the edit that hid the reuse. Both functions now bucket on the key's type and material through a `key_material` helper, and four discriminators pin it. Proven red-then-green rather than asserted: with `key_material` patched back to the whole string, the two "one key, two comments" tests fail and the two converse tests stay green, which is what makes the fix a narrowing rather than a widening.

**`docs/onboard-an-application.md` §2 was half-moved.** Its `ssh-keygen` command still generated `<company>-<app>-<environment>` while the Check one line below looked for `<company>-<app>-<stack>`, so an operator following it literally would have created a file the next line could not find. Its frequency table and §2's lead line still counted the deploy authorisation per environment, which is the requirement's own "two stacks share an environment" scenario met from the wrong side, in the document this change exists to make correct. Both corrected, and §4.2's fingerprint check with them.

**`docs/bootstrap-a-new-host.md` gained §6.1.1.** The host's own vars file is the one artefact stage 6 requires the operator to **create**, and it had no step, no path and no Check -- only a "not in this file" row inside a table about `group_vars`. It has all three now.

**Round one's finding 6 was reported as applied and was not in that commit.** The script that applied the batch aborted on an earlier assertion, and the edit after the failure never ran; the report was written from the intent rather than from the result. This is the third instance of that shape on this branch -- task 2.5 discloses one, the round-one sweep found another -- and the pattern is what matters rather than the line. Every edit in this round was verified by re-reading the file afterwards, not by the exit status of the thing that made it.

**One finding was considered and declined.** `.github/workflows/host-converge.yml` checks that a stack's declared `group_vars` file exists and does not check for its host vars file, so a `workflow_dispatch` run bypasses the pull-request check that does. It is left, for the reason `ansible/playbooks/host-baseline.yml` gives at play scope in its own commentary: restating a role's required inputs in a second place that nothing keeps in step with the roles buys an earlier refusal at the cost of a new drift class. The merge path is covered by `.github/tests`, which runs unconditionally; the dispatch path reaches `deploy_user`'s own refusal, which names the input. The cost is a partially-converged host, which is the accepted gap that commentary already describes. It is recorded in `docs/backlog.md` `put-the-remaining-host-scoped-variables-on-the-host-axis` rather than left in this file alone.
