Verification commands referenced below, from this project's conventions:

- `python3 -m unittest discover --start-directory .github/tests`, from the repository root
- `ansible/scripts/run-molecule test --all`, run from a role directory — read the SCENARIO RECAP, not the exit code
- `pre-commit run --all-files`
- `openspec validate --all`

**This change's subject is a static read of committed files, so `.github/tests` is the mechanism** — the third row of this project's test table. The selector parses scenario YAML and maps changed paths; every obligation in the delta is decidable from committed content, and none of it needs a container. Molecule is *not* this change's test mechanism, and the suite is run here only to establish that nothing about what a role does changed.

**Two things the delta's obligations turn on, which the tests have to be written against rather than around.** First, the graph is derived at run time and nothing commits it, so a test asserting a hardcoded expected graph would be asserting today's tree rather than the derivation — the closure is therefore asserted twice, once over a fixture graph with a known answer and once over the real tree. Second, the widening rule's failure mode is silent, so the check that matters most is the one asserting an *unrecognised* path selects everything; a check that only exercises recognised paths passes on a selector that narrows to nothing.

**Baseline, recorded before anything was written.** `python3 -m unittest discover --start-directory .github/tests` reports 646 tests with one failure — `TestEveryComposeFileDeclaringAServiceImageIsCovered`, which walks into `.molecule-home/` and flags six collection fixtures. It is pre-existing, owned by `docs/change-queue.md` entry 68, and green in continuous integration, which never provisions Molecule. Any other failure below is this change's.

**Section 1 comes first on purpose** — the tests are derived from the delta before the implementation exists.

## 2. The selector

- [x] 2.1 Add the selector under `ansible/scripts/`, beside `run-molecule`. The location is load-bearing and `design.md` Decision 6 carries why: a path under `ansible/` is a trigger under the existing filter and an unattributable one under Decision 3, so editing the selector runs the whole suite — where a selector under `.github/` would change what every later pull request runs while running nothing itself. Python rather than shell, because `.github/tests` imports the derivation and because the YAML parsing is not shell's work.
- [x] 2.2 Implement the derivation and its refusals, per sections 1.1, 1.2, 1.2a and 1.2b. The read set is the tracked scenario files, each role's `meta/main.yml`, **and each role's own `tasks/` and `handlers/` — the last read to refuse, not to follow**, per `design.md` Decision 2. `molecule.yml`'s contents are never read; only its path is, and only to identify the role a scenario belongs to.
- [x] 2.2a Place the permitted-instance entry **in the selector**, not in the test module, keyed on file, construction and resolved target in the form `PERMITTED_CONTROLLER_READS` uses. The refusal executes in the selector, so that is where the permission has to live; a copy in `.github/tests` would be the stale list `design.md` Decision 1 spends its argument against, and a selector shipping the refusal without the entry turns the required check red on **every** pull request in the repository. 1.2b's test reads this entry rather than restating it. **Ship it in the same commit as the refusal**, never a commit later.
- [x] 2.3 Implement the reverse closure, terminating on a cycle, and **restrict it to the discovered set** — the one sentence that reconciles Decision 3's three cases. Restriction happens after the closure and before the matrix; doing it earlier drops a scenario-less role's convergers along with the role.
- [x] 2.4 Implement attribution and widening per `design.md` Decision 3 — including its third case, a closure whose restriction leaves nothing — and the empty-selection refusal, which lives here in the selector rather than in the workflow. The workflow propagates its exit status and adds no refusal of its own; 1.7 asserts each half where it lives.
