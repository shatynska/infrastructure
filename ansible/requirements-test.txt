# Pinned pip test dependencies for this project's Ansible test framework
# (Molecule), adopted by openspec/changes/bootstrap-ansible-host-baseline's
# design.md Decisions section. These arrive via pip rather than Galaxy, but
# the same "any external role or collection used for any purpose is pinned
# to an exact version" convention (AGENTS.md) is extended to them here —
# never a floating range, for the same reason an unpinned Galaxy role isn't
# actually pinned: two installs at different times could otherwise resolve
# different versions and silently change what a test run actually checks.
#
# Install with: pip install -r ansible/requirements-test.txt
#
# ansible-core is pinned here too, and that is the correction this file
# needed (openspec/changes/repair-ansible-test-harness). Leaving it out did
# not leave it unconstrained -- it left it resolved by whatever pip picked
# on the day, which is exactly the failure the convention above exists to
# prevent. A fresh install used to resolve ansible-core 2.21 against a
# 2023-era Molecule docker driver, and the suite died at the first `destroy`
# action with "Conditionals must have a boolean result", before any scenario
# reached `create`.
#
# The fix moved these pins FORWARD rather than pinning ansible-core back to
# something the old driver tolerated. ansible-core 2.18.19 would have
# satisfied both molecule-plugins 23.5.3 and ansible-lint 26.8.0, and was
# rejected: it would freeze this repository's ansible-core at a version
# chosen by a three-year-old plugin release, and every future tool here
# would have to be compatible with that choice. A current molecule-plugins
# exists and works on current ansible-core, so the constraint was never
# real -- only stale. See that change's design.md, "Pins move forward, not
# backward".
#
# Verified together, in this combination, on Python 3.12.
ansible-core==2.21.3
molecule==26.8.0
molecule-plugins[docker]==26.7.15
